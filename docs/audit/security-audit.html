Authentication Bypass

SEC-001: JWT Secret Validation Bypass

Risk: An attacker can bypass authentication entirely by providing any JWT when the secret is empty.

Location: authserver/internal/config/config.go:117-119

The validation logic only checks length if the secret is non-empty. An empty string ("") passes validation, but is then used as the HMAC key, allowing any JWT to be valid.

Vulnerable Code

func (c *Config) validate() {
    if c.JWTSecret != "" && len(c.JWTSecret) < 32 {
        panic("JWT_SECRET must be >= 32 characters or empty")
    }
}

Recommended Fix

func (c *Config) validate() error {
    if len(strings.TrimSpace(c.JWTSecret)) < 32 {
        return fmt.Errorf("JWT_SECRET must be >= 32 non-whitespace characters")
    }
    return nil
}

Weak Password Handling

SEC-008: Password Strength Check Insufficient

Only checks for length >= 8. Missing complexity requirements (uppercase, lowercase, digits, special characters).

Current validation:

if len(req.NewPassword) < 8 {
    writeJSONError(w, http.StatusBadRequest, "password must be at least 8 characters")
    return
}

Recommended validation:

func validatePasswordStrength(password string) error {
    if len(password) < 12 {
        return errors.New("password must be at least 12 characters")
    }
    var hasUpper, hasLower, hasDigit, hasSpecial bool
    for _, ch := range password {
        switch {
        case unicode.IsUpper(ch): hasUpper = true
        case unicode.IsLower(ch): hasLower = true
        case unicode.IsDigit(ch): hasDigit = true
        case unicode.IsPunct(ch) || unicode.IsSymbol(ch): hasSpecial = true
        }
    }
    if !(hasUpper && hasLower && hasDigit && hasSpecial) {
        return errors.New("password must contain uppercase, lowercase, digit, and special character")
    }
    return nil
}

Recommendations

Immediate Actions (24-48 hours)

1. Fix JWT secret validation to reject empty strings
2. Implement row-level locking for password changes
3. Force STARTTLS before AUTH in SMTP submission
4. Add origin validation for WebSocket connections
5. Sanitize all user inputs in SQL reducers

Short-term (1-2 weeks)

1. Replace SHA256 key derivation with HKDF
2. Implement CSRF tokens for all state-changing operations
3. Add distributed rate limiting (Redis/PostgreSQL)
4. Enable comprehensive security headers
5. Implement proper error handling without exposing internals

Long-term (1-2 months)

1. Extract common JWT/middleware to shared packages
2. Implement mTLS for inter-service communication
3. Add Prometheus metrics and centralized logging
4. Conduct penetration testing on all protocols
5. Implement automated security scanning in CI/CD

Architecture Improvements

1. Decouple services: Use event-driven architecture (NATS/RabbitMQ)
2. Zero Trust: Implement service mesh with mTLS
3. Least Privilege: Use PostgreSQL RLS policies
4. Secrets Management: Integrate with HashiCorp Vault
5. API Gateway: Centralize authentication and rate limiting
