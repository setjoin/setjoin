# BZ234 spread audit

Base: `a468dcc2` on `codex/identity-modernization-i0`.

Codex independently re-enumerated all 46 pre-change `BZ234` raise sites before
editing. The original registry described only transition preflight, while the
code also used the value for malformed arguments, no-oracle target failures,
authorization/session races, state conflicts, and operational preflight.

## Disposition rule

- `BZ241` is only malformed, missing, out-of-range, or internally inconsistent
  request arguments evaluated before target/state lookup.
- `BZ234` retains state/preflight conflicts, no-oracle unavailable/not-found
  outcomes, authorization/session races, and actor/target mismatch.
- Actor/target checks in compound validation guards were split so malformed
  fields can project as 400 without weakening the actor boundary.
- No site was moved to 403 or 404. Doing so would require a separate API
  disclosure review because several predicates deliberately combine absence,
  ownership, reach, and lifecycle state.

## Kept on BZ234

The remaining original sites match one of the retained conflict families:

- target/authorization unavailable or no-oracle not-found:
  `identity_auth_link` target unavailable;
  `identity_auth_link_authorized` authorization unavailable;
  `identity_auth_unlink` link not found;
  transition execute/expire/read/request/rollback not found;
  transition preview target not reachable;
- session/state races:
  authorized-link session revoked or authorization consumed;
  elevation session inactive;
  transition cancel/retry/rollback/rollback-preview invalid current state;
  illegal or concurrently changed transition state;
- lifecycle/security preflight:
  unlink requiring a transition;
  media security effects pending;
  transition admission prerequisites disabled;
  non-directory lifecycle ownership, missing lifecycle link, unsupported source
  pair, re-preview refusal, create-without-current-object refusal, backfill
  blockers, and invalid canary cohort.

After the compound guards were split, current source contains 34 BZ234 raise
sites with 27 distinct messages and 15 BZ241 sites with 15 distinct messages.
`scripts/check-reducer-error-codes.sh` pins those audited message ceilings and
also requires every raised code to appear in both the registry and the
reducererr wire contract.

### 2026-08-13 follow-up audit

The later V204 source-to-source identity transition added one genuinely new
BZ234 preflight message: `source pair is not supported`. It is distinct from
the older directory-to-local pair failure because the remediation and allowed
pair set differ. The other apparent spread was syntactic or redundant and was
collapsed: the admission-prerequisite raise now matches the existing message
shape, source ownership reuses `person is not directory lifecycle-owned`, and
malformed source preview reuses the BZ241 `invalid identity transition preview`
message. The audited ceilings are therefore 29 distinct BZ234 messages and 15
distinct BZ241 messages; no disclosure class or wire projection changed.

## Accepted and rejected plan findings

Accepted:

- allocate BZ241 as `ClassInvalidArguments`;
- add a structural registry/classifier/message-budget guard;
- remove the two unreachable `create -> new` CASE arms while preserving the
  advertised, fail-closed `create` decision;
- preserve BZ234 for real transition/preflight conflict semantics.

Corrected:

- the plan called `identity_auth_link` target-unavailable “pure validation.”
  It is a no-oracle target-state check and remains BZ234;
- the plan said the mint fence had four BZ235 sites. It has five;
- the split was applied consistently to auth link, authorized link, and unlink
  actor boundaries rather than changing actor mismatch to HTTP 400.
