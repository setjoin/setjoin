# Feature registry and focused architecture checks

This guide is the contributor contract for Setjoin's finite feature registry
and the Architecture Deepening Round 2 verification front door. Runtime policy
still belongs to reducers and the owning service; these tools derive and verify
contracts, they do not become a second source of business authority.

## Authority and rollout model

- `shared/toggle/toggle.go` owns the sorted `Definition{Key, Default}` catalog.
- `shared/pwhash/auth_log.go` owns the finite authentication-provider catalog;
  provider-specific feature keys are derived from it.
- `mailserver/sql/generated/feature_toggle_registry_current.sql` is generated
  classifier input. Never edit it by hand.
- V183 introduced the database registry state, reducer-authoritative SET,
  unknown-only DELETE, observe/enforce transitions, audit, trigger fence, and
  notification. V183 and `registry-v183.json` are immutable.
- Observe preserves the historical runtime behavior of retained unknown rows so
  a rolling deployment can be inspected and cleaned. Enforce ignores unknown
  rows and rejects new unknown writes. Moving to enforce requires the installed
  digest to match and the unknown-row count to be zero; returning to observe
  remains available even under digest skew.
- Releases targeting schema 183 or later carry the signed
  `feature_registry` contract. The updater checks it before host mutation,
  after migrations, and after rollback. Enforce cannot cross a digest change;
  an observe rollout must name compatible rollback digests.

## Add or change a feature key

1. Add a typed constant and exactly one default to the sorted `definitions`
   slice in `shared/toggle/toggle.go`. Do not pass a raw key to `IsEnabled`.
   Dynamic suffix families must first be reduced to a reviewed finite source
   such as `pwhash.AuthProviders()`.
2. Find the next unused schema migration number. Never reuse or edit V183 (or
   another committed registry projection).
3. From the repository root, run the developer-only writer, replacing `V195`
   with that next number:

   ```bash
   go run ./shared/toggle/cmd/feature-registry-gen --write --migration V195
   ```

   The writer refuses a skipped/reused migration number and creates a versioned
   snapshot, its migration, a two-file checksum document, and the current SQL
   projection. Review every generated byte. CI never invokes `--write`.
4. Update the signed release draft's `feature_registry.catalog_digest` and its
   sorted `compatible_modes`. When the digest changes in observe mode, include
   the installed/rollback cohort digest in
   `compatible_rollback_digests`. Do not claim enforce compatibility across a
   digest change.
5. Run:

   ```bash
   go run ./shared/toggle/cmd/feature-registry-gen --check
   bash scripts/verify-architecture-r2.sh registry
   bash scripts/verify-architecture-r2.sh full
   ```

`--check` verifies every versioned migration/snapshot checksum and requires the
latest snapshot, generated SQL, and latest migration to match the compiled
catalog. The DB lane proves known/unknown writes, audit/NOTIFY, both cutover race
orders, N-1 handler behavior, updater preflight/post-commit/rollback, and the
digest-independent observe rollback. An intentionally deleted unknown row is
not resurrected by rollback.

## Five common architecture recipes

### Add a route

Register it through an existing reviewed middleware wrapper, update the owning
runtime inventory test/golden, and either document the exact operation in
`mailserver/api/openapi.yaml` or add a reviewer-approved exact pending entry.

```bash
bash scripts/verify-architecture-r2.sh route
bash scripts/verify-architecture-r2.sh route --self-test
```

Expected: an exact-operation count followed by `route-inventory: PASS`. The
self-test prints the caught `E_ROUTE_UNDOCUMENTED` problem, cause, fix, and
rerun command, then exits successfully.

### Add an app prefix

Edit only `RAIL_APPS` in `mailserver/webmail/src/lib/nav/navConfig.ts`. Use an
exact segment prefix, add query/hash, near-prefix, absent-capability, Guest, and
zero-app tests, then run:

```bash
bash scripts/verify-architecture-r2.sh app
```

### Add a worker launch

Start the worker through `launchWorker`; add its reviewed stop/drain semantics
to `worker_semantics.json` and update the AST-derived golden. Do not introduce a
second supervisor or a direct `go worker.Run(...)` call.

```bash
bash scripts/verify-architecture-r2.sh worker
```

### Add a feature key

Follow the versioned registry workflow above. A key is not complete until the
typed catalog, generated SQL, signed release compatibility, reducer/API/UI
behavior, and observe/enforce tests agree.

```bash
bash scripts/verify-architecture-r2.sh registry
```

### Add a native bridge member

Change the TypeScript authority in
`mailserver/webmail/src/lib/native/types.ts`, regenerate its deterministic
projection, implement the supported shell seams, and run the production
recorder checks:

```bash
node scripts/native-contract-conformance.mjs --write
bash scripts/verify-architecture-r2.sh native
```

The checker derives capabilities with the pinned TypeScript compiler and checks
actual Electron handler maps, Tauri command registration/rendered bridge JS,
and Harmony registration/proxy/shim use. Platform capability differences are
allowed; advertising an unsupported member is not.

## Front door, diagnostics, and timing evidence

```bash
bash scripts/verify-architecture-r2.sh --doctor
bash scripts/verify-architecture-r2.sh --help
bash scripts/verify-architecture-r2.sh          # hermetic quick lane
bash scripts/verify-architecture-r2.sh full     # DB + canonical deterministic gates
```

Each lane publishes a schema-versioned, hash-bound manifest atomically under
`test-results/architecture-r2/`. Failed or interrupted work never occupies a
passing pointer. The PR timing contract uses one warmup and five samples; the
scheduled/promotion gate uses two warmups and twenty samples with nearest-rank
p95. Both use the same validator and require each duration to stay within five
minutes (scheduled p95: sample 19 of 20) and planted diagnostics within 30
seconds.

```bash
bash scripts/verify-architecture-r2.sh benchmark --class warm --samples 5 --warmup 1
bash scripts/check-architecture-r2-dx-metrics.sh --require

bash scripts/verify-architecture-r2.sh benchmark --class warm --samples 20 --warmup 2
```

Fingerprints contain toolchain/lock digests and coarse machine classes, never a
host name, user name, serial number, credential, or path outside the checkout.
Cold runs are a separate informational population and never mix with warm
evidence.

## Recovery from common failures

- `E_TOGGLE_REGISTRY_DRIFT`: do not edit a historical artifact. Confirm the
  typed authority, generate the next unused migration locally, inspect it, and
  rerun `--check`.
- `feature registry release contract differs`: return the database to observe
  if needed; use a target/rollback cohort whose signed digest/mode declarations
  match the live state. Never bypass updater preflight.
- `unknown_rows`: remove or register every reported row through the audited
  admin flow before enforce.
- `E_ARCH_R2_METRICS`: preserve the failed evidence, correct the named
  population/hash/threshold problem, and rerun the exact command in the error.
