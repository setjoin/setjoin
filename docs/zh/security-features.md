## 概述

SetJoin 采用纵深防御策略，在邮件传输的多个环节实施安全检查：

```
入站邮件 → [SPF/DKIM/DMARC] → [RBL/DNSBL] → [反垃圾邮件评分] 
         → [ClamAV 扫描] → [DLP 规则] → [URL 保护] → 收件箱
```

## 反垃圾邮件 (Anti-Spam)

### 多层评分机制

1. **RBL/DNSBL 查询**（接入 Spamhaus DBL + 国内反垃圾邮件联盟）
2. **Bayesian 分类器**：基于训练数据的统计分类
3. **启发式规则**：基于邮件头、正文、附件特征的评分
4. **灰名单 (Greylisting)**：对未知发件人临时拒绝，要求重试

### 中国特别配置

- 接入 **中国互联网协会反垃圾邮件中心 (ASP)** 的 RBL 数据
- 支持 **《互联网电子邮件服务管理办法》** 的合规要求
- 配合工信部垃圾邮件投诉处理流程

### 配置反垃圾邮件策略

在管理后台 → **功能开关** 中启用/禁用反垃圾邮件引擎。

## SPF/DKIM/DMARC 邮件认证

### SPF (Sender Policy Framework)

验证发件服务器是否被授权发送该域名的邮件。

**配置方式**：在域名的 DNS 中添加 TXT 记录：
```
v=spf1 mx ip4:<服务器IP> -all
```

### DKIM (DomainKeys Identified Mail)

对发件邮件进行数字签名，确保邮件内容未被篡改。

**密钥管理**：在管理后台 → **域名管理** → 选择域名 → 查看 DKIM 公钥。
将公钥作为 TXT 记录添加到 DNS：
```
default._domainkey.example.com TXT "v=DKIM1; k=rsa; p=<公钥内容>"
```

**国密模式** (Stage 3.2)：支持 SM2-SM3 DKIM 签名。

### DMARC (Domain-based Message Authentication, Reporting & Conformance)

结合 SPF 和 DKIM 的域名级邮件认证策略。

**配置 DNS 记录**：
```
_dmarc.example.com TXT "v=DMARC1; p=quarantine; rua=mailto:dmarc@example.com; ruf=mailto:forensic@example.com"
```

**DMARC 策略**：
- `none`：仅监控，不采取行动
- `quarantine`：可疑邮件进入隔离区
- `reject`：直接拒绝不符合策略的邮件

**查看报告**：管理后台 → **DMARC 报告** 查看聚合和取证报告。

## 防病毒扫描 (ClamAV)

SetJoin 集成 ClamAV 开源防病毒引擎：

- 自动扫描入站和出站邮件的所有附件
- 支持病毒库自动更新
- 检测到恶意软件的邮件自动隔离

## 数据丢失防护 (DLP)

DLP 防止包含敏感信息的邮件外泄。

### DLP 规则类型

| 规则 | 说明 | 示例 |
|------|------|------|
| 关键词匹配 | 检测邮件内容中的敏感关键词 | 身份证号、银行卡号、手机号 |
| 正则表达式 | 基于正则模式匹配 | `\d{18}` 匹配 18 位身份证号 |
| 附件类型 | 阻止特定类型附件外发 | `.docx`, `.xlsx`, `.pdf` |
| 文件大小 | 限制附件总大小 | 单封邮件不超过 50 MB |

### 符合中国法规的 DLP 规则

- **《个人信息保护法》**：检测身份证号、手机号、银行卡号
- **《数据安全法》**：检测涉密关键词和分类标记
- **行业合规**：金融行业客户信息、医疗健康数据、教育学生信息

## URL 保护 (Link Protection)

### 功能

- 对邮件中的 URL 进行重写，用户点击时先经过安全检查
- 接入 Google Safe Browsing API 检查恶意链接
- 支持自定义允许/阻止域名列表

### 工作原理

```
原始链接: https://malicious.example.com/phishing
↓ 重写
安全链接: https://mail.example.com/link-protect?token=abc123...
↓ 点击时检查
结果: 安全 → 跳转 / 危险 → 警告页面
```

## 隔离管理 (Quarantine)

### 隔离原因

邮件可能因以下原因被隔离：
- 反垃圾邮件评分超过阈值
- 包含病毒/恶意软件
- 违反 DLP 规则
- DMARC 策略为 `reject` 的邮件

### 隔离操作

在管理后台 → **隔离管理** 中：
- **放行**：将邮件释放到收件人邮箱
- **拦截**：永久删除邮件
- **批量操作**：选择多封邮件统一处理

### 自动清理

隔离区的邮件在保留期满后自动删除（默认 30 天，可在保留策略中配置）。

## 频率限制 (Rate Limiting)

### 限制维度

| 维度 | 说明 |
|------|------|
| IP 地址 | 按客户端 IP 限制请求频率 |
| 用户 | 按认证用户限制操作频率 |
| 邮箱 | 按邮箱限制发送频率 |
| 域名 | 按域名限制入站/出站流量 |

### 可配置参数

在管理后台 → **限制** 中配置：
- 速率 (Rate)
- 突发 (Burst)
- 时间窗口 (Window)

## 威胁检测管线

SetJoin 的认证端点在每个请求前执行 8 步威胁检测管线：

| 步骤 | 检查项 | 说明 |
|------|--------|------|
| 1 | 威胁情报订阅 | Spamhaus DROP/EDROP 列表 |
| 2 | IP 规则 | 自定义 IP 白名单/黑名单 |
| 3 | GeoIP 封禁 | 按国家/地区封禁（如 CN, RU, KP） |
| 4 | 账户锁定 | 连续失败后临时锁定 |
| 5 | 密码喷洒检测 | 检测试探多个用户名的攻击 |
| 6 | CAPTCHA 挑战 | 多次失败后要求验证码 |
| 7 | Tarpit | 可疑 IP 的渐进延迟 |
| 8 | 速率限制 | 请求频率限制 |

### 密码喷洒检测

- 检测窗口：300 秒内尝试 5 个以上不同用户名
- 锁定时间：30 分钟
- 影响：被锁定的 IP 无法尝试任何登录

## TLS 安全

### 最低要求

- TLS 1.2 及以上，禁用 SSLv3/TLS 1.0/1.1
- 推荐 TLS 1.3
- SMTP 端口 587 强制 STARTTLS

### SMTP TLS 报告 (TLS-RPT)

支持 TLS-RPT (RFC 8460)，接收邮件发送方的 TLS 投递报告。

### MTA-STS

支持 MTA-STS (RFC 8461)，发布强制 TLS 传输策略。

### DANE/TLSA

支持基于 DNSSEC 的 DANE 认证（在 DNS 中发布 TLSA 记录）。

## 安全审计

### 审计日志

所有安全相关事件记录在审计日志中：
- 登录成功/失败
- 密码修改
- 权限变更
- 配置修改
- 隔离操作
- DLP 违规

在管理后台 → **审计日志** 中查看，可导出为 CSV/JSON。

### 安全告警

以下事件会触发告警：
- 密码喷洒攻击检测
- 多次认证失败
- DLP 规则命中
- 管理员账户变更

在管理后台 → **告警管理** 中查看和处理。

## 中国法规合规

### 网络安全法（《中华人民共和国网络安全法》）

- 实名认证要求：所有用户需通过实名邮箱注册
- 日志保留：网络日志保存不少于 6 个月
- 安全评估：系统上线前完成安全评估

### 数据安全法（《中华人民共和国数据安全法》）

- 数据分类分级：支持对邮件内容按敏感度分类
- 数据出境管理：DLP 规则可阻止敏感数据通过邮件出境
- 数据安全审查：定期安全审查和风险评估

### 个人信息保护法（《中华人民共和国个人信息保护法》，PIPL）

- 个人信息识别：DLP 规则自动检测身份证号、手机号等
- 最小必要原则：管理员权限按最小必要原则分配
- 删除权：用户可请求删除其个人信息
