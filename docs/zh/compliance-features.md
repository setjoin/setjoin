## 电子取证 (eDiscovery)

电子取证功能允许授权管理员创建和管理取证案件，对指定邮箱实施诉讼保留并导出相关邮件。

### 创建取证案件

1. 登录管理后台 → **电子取证 (eDiscovery)**
2. 点击 **新建案件**
3. 填写案件信息：
   - **案件名称**：描述性名称（如"2026-Q1-合同纠纷"）
   - **描述**：案件背景和目的
   - **目标邮箱**：需要取证的邮箱列表
   - **日期范围**：限定取证的时间范围
4. 保存案件

### 诉讼保留 (Litigation Hold)

对目标邮箱启用诉讼保留后：
- 用户无法删除或修改被保留的邮件
- 即使用户尝试清空已删除文件夹，邮件仍可被取证检索
- 保留不影响用户正常收发邮件

**操作**：在案件详情页点击 **设置保留** 或 **解除保留**。

### 搜索结果导出

- 导出格式：PST、mbox、EML
- 支持增量导出（仅导出新增匹配邮件）
- 导出过程在后台异步执行，完成后可下载

## 内容搜索 (Content Search)

内容搜索允许管理员跨多个邮箱搜索邮件内容，支持 KQL (Keyword Query Language) 查询语法。

### KQL 查询语法示例

```kql
# 关键词搜索
"合同纠纷" OR "保密协议"

# 字段搜索
from:external@example.com AND subject:"报价"

# 日期范围
received>=2026-01-01 AND received<=2026-06-30

# 附件类型
attachment:*.pdf OR attachment:*.docx

# 组合查询
(from:legal@example.com OR from:hr@example.com) AND subject:"机密"
```

### 搜索结果操作

- **预览**：查看邮件摘要（主题、发件人、日期、正文前 200 字符）
- **导出**：将匹配的邮件导出
- **保存搜索**：保存查询条件供后续重用

### 权限控制

只有超级管理员和具有 eDiscovery 权限的管理员可以：
- 创建和执行内容搜索
- 查看搜索结果
- 导出搜索命中邮件

所有搜索操作均有审计日志。

## 保留策略 (Retention Policies)

保留策略定义邮件的保留期限和过期后处理方式。

### 创建保留策略

1. 登录管理后台 → **保留策略 (Retention)**
2. 点击 **创建策略**
3. 配置策略参数：

| 参数 | 说明 |
|------|------|
| 名称 | 策略的描述性名称 |
| 保留时长 | 邮件创建后保留的天数 |
| 范围 | 全局（所有用户）/ 按邮箱 / 按标签 |
| 标签筛选 | 仅对带有特定标签的邮件生效 |
| 过期操作 | 归档到长期存储 / 永久删除 |

### 保留策略示例

| 策略名称 | 保留天数 | 范围 | 过期操作 |
|----------|----------|------|----------|
| 财务邮件 7 年 | 2555 | 标签:财务 | 归档 |
| 普通邮件 2 年 | 730 | 全局 | 永久删除 |
| 已删除邮件 30 天 | 30 | 标签:已删除 | 永久删除 |

### 等保合规保留要求

- **等保二级**：日志保留 6 个月，邮件按需保留
- **等保三级**：日志保留 12 个月以上，关键业务邮件保留 3-7 年
- **《网络安全法》**：网络日志保留不少于 6 个月

## 归档 (Journaling)

归档功能将所有收发邮件备份到不可变存储，满足合规审计需求。

### 归档配置

- 按邮箱启用/禁用归档
- 归档存储目标：SeaweedFS / S3 兼容存储 / 阿里云 OSS
- 不可变性：归档后的邮件不可修改或删除

### 合规价值

- 满足《网络安全法》的日志留存要求
- 满足《数据安全法》的数据完整性要求
- 为企业内部审计和外部监管检查提供完整记录

## 审计日志 (Audit Log)

审计日志记录所有管理操作和系统事件，不可篡改。

### 记录的事件类型

| 类别 | 事件示例 |
|------|----------|
| 用户管理 | 创建用户、修改用户、删除用户、重置密码 |
| 权限变更 | 授予/撤销管理员角色 |
| 配置变更 | 修改域名配置、修改保留策略、修改功能开关 |
| 认证事件 | 登录成功、登录失败、会话撤销 |
| 取证操作 | 创建案件、设置保留、导出结果 |
| 内容搜索 | 执行搜索、导出搜索结果 |
| 隔离操作 | 放行邮件、拦截邮件 |

### 查看审计日志

1. 登录管理后台 → **审计日志 (Audit)**
2. 使用筛选条件：
   - **操作者 (Actor)**：按管理员用户名筛选
   - **操作 (Action)**：按操作类型筛选
   - **日期范围**：按时间范围筛选
3. 查看详情：点击每条记录查看完整的操作参数

### 导出审计日志

支持导出为 CSV 或 JSON 格式，用于：
- 外部审计机构审查
- 合规报告编制
- 安全事件调查

## 等保 (MLPS) 合规映射

以下表格映射 SetJoin 功能到《网络安全等级保护基本要求》(GB/T 22239-2019) 的控制项：

### 等保二级 (Level 2)

| 控制项 | 等保要求 | SetJoin 实现 |
|--------|----------|-----------|
| 身份鉴别 (A.2.1.1) | 身份标识和鉴别 | 密码 + TOTP MFA + WebAuthn |
| 访问控制 (A.2.1.2) | 基于角色的访问控制 | RBAC: super_admin/user_admin/read_only/auditor |
| 安全审计 (A.2.1.3) | 审计日志生成和保护 | 审计日志模块，不可篡改 |
| 通信保密性 (A.2.1.5) | 通信过程中数据的保密性 | TLS 1.2+，STARTTLS |
| 数据完整性 (A.2.1.6) | 数据传输完整性 | DKIM 签名 |

### 等保三级 (Level 3) — 额外要求

| 控制项 | 等保要求 | SetJoin 实现 |
|--------|----------|-----------|
| 双因子认证 | 两种或以上鉴别技术组合 | 密码 + TOTP/WebAuthn/Push MFA |
| 三权分立 | 系统管理/安全/审计分设 | 四种管理员角色分离 |
| 国密算法 | 使用国产密码算法 | SM2/SM3/SM4 (Stage 3.2) |
| 审计日志保护 | 审计记录保护，避免未预期的删除/修改 | 不可变审计日志，导出保护 |
| 数据备份恢复 | 异地实时备份 | 增量备份 + 灾难恢复引擎 |

## 信创 (Xinchuang) 审计要求

信创环境下对审计和合规有额外要求：

### 审计日志存储

- 审计日志必须存储在国产数据库中（PolarDB for PostgreSQL）
- 审计日志表使用 SM4 加密
- 审计日志查询接口使用国密 TLS 加密

### 审计日志保留

- 信创合规建议保留不少于 3 年
- 日志归档到国产存储（阿里云 OSS / 华为云 OBS）
- 归档日志使用 SM2 签名确保完整性

### 审计报告

- 支持按日期范围生成合规审计报告
- 报告格式：PDF（带 SM2 数字签名）
- 报告内容：用户操作统计、权限变更记录、安全事件摘要
