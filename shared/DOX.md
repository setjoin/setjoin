# shared — cross-cutting Go packages

Module path: `setjoin.com/shared`. Consumed by `authserver`, `mailserver/gateway`, and (in future) any additional service. Go workspace member (`go.work`).

## Purpose

Provides the stable Go packages shared across both servers: auth contract, crypto, config loading, DNS, environment helpers, generics, HTTP utilities, JWT types, middleware, PAL (platform abstraction), permissions, PostgreSQL pool, password hashing, spam primitives, threat detection pipeline, feature toggles, input validators, and webhook signing. No business logic lives here — only contracts, adapters, and reusable algorithms.

## Ownership

This doc owns: every package under `shared/`. It does not own:
- The authserver or mailserver implementations that consume these packages.
- The feature_toggles or threat_feed_blocks PostgreSQL schema (owned by `mailserver/sql/`).

**Live protocol-session revocation.** `threat.ProtocolSessions` is the shared
IMAP/SMTP connection registry. An all-before revocation raises a monotonic
per-user watermark under the same mutex used to register sessions, closes every
existing session authenticated at or before it, and rejects a concurrent late
registration carrying the already-captured authentication time. Protocol
adapters must capture that time at credential verification and pass it
unchanged; sampling a new time at registration reopens the race.

### identity
- **SSO input bounds**: `ValidateSSOGroupClaims` caps an IdP assertion at 1,000 group names; `ValidateSSOGroupMappings` caps the operator document at 100 mappings. - **`ValidateAccountID(ctx, q, reqMailboxID, userID, delegates DelegateGrants) (own bool, grants []string, err error)`** (#13 shared-mailbox widening): `own=true` iff `reqMailboxID == ResolvePrimaryMailbox(userID)`; otherwise, when `delegates` is non-nil, `grants` = the caller's `mailbox_delegates.permission` levels on `reqMailboxID` (valid account = `own || len(grants)>0`; the CALLER gates per-method on the levels). - **`CanonicalizeAddress(raw string) CanonicalAddress`** (normalization wave, 2026-06-18): the input canonicalizer — **trim + ASCII-fold lower + RFC-5322 display-name strip ONLY**. Deliberately NOT unicode `strings.ToLower` (avoids the Turkish dotted/dotless-I and ß folding hazards — a non-ASCII rune passes through unchanged, pinned by a live test). It **NEVER rejects**: a bare UPN (`alice@corp`, no dot), a Kerberos principal (`alice/admin@CORP`), or garbage is returned trimmed+folded so it still resolves against `ad_upn`/`aliases`. Idempotent. - **ThreatInterceptor**: 9-step pre-auth pipeline shared by HTTP middleware, IMAP, and SMTP. Constructed via `New(pool, toggles, geoip, cfg, logger, policyEngine)`. The sequencing is a **declared step list**, not buried control flow: `buildPipeline()` returns `[]step{...}` (8 step-methods, in order: threat_feed → ip_rules → geo_block → lockout → spray → captcha_tarpit → rate_limit → policy — the conceptual steps 6+7 below are one combined `captcha_tarpit` step that shares the single `auth_attempts` query), and `runPipeline()` runs them, returning the first non-`ActionProceed` result. Each step is a `func(ctx, *ConnectionMeta) (InterceptorResult, string, time.Duration)` method that self-gates on its own toggle; `ConnectionMeta.SkipCaptcha` gates the captcha step (IMAP/SMTP set it). Order/short-circuit/gating are unit-testable against a `[]step` of fakes (`pipeline_test.go`). `shared/threat/interceptor.go`
  - Step 1 — Threat feed check: queries `threat_feed_blocks` for CIDR match.
  - Step 2 — IP rules: queries `ip_rules`; allow = immediate proceed, block = immediate reject.
  - Step 3 — Geo-block: checks `blockCountries` map from `GEO_BLOCK_COUNTRIES`.
  - Step 4 — Lockout: checks `auth_lockouts` for IP, user, or IP+user composite key.
  - Step 5 — Spray detection: calls `detect_spray($ip, windowSecs, maxUsers)` PL/pgSQL function; on trigger: inserts lockout, audit_log, pg_notify on `alert:spray`.
  - Step 6 — CAPTCHA gate: triggers after `CaptchaThreshold` failures in `CaptchaWindowMins`; issues math CAPTCHA challenge signed with HMAC-SHA256.
  - Step 7 — Tarpit: progressive delay (500ms × fail_count, max 15s) after `TarpitThreshold` failures or high-risk country.
  - Step 8 — Rate limit: per-IP per-protocol per-minute counter via `rate_limit_counters` upsert.
  - Step 9 — Conditional access policy evaluation: `PolicyEngine.Evaluate()`.
- **Adapter seams (steps 4/5/8 + post-auth)**: `intercept()`/`recordOutcome()` **compose** three narrow adapters instead of inlining SQL — mirroring the `PolicyStore`/`PolicyEngine` pattern. Each owns one DB seam (SQL lifted verbatim into `store.go`) and is unit-testable in isolation with a fake store; the composed behaviour stays byte-identical.
  - **`LockoutManager`** (`lockout.go`) — `Check` (no-op on empty username; returns max remaining across the three keys ip/user/ip_user), `Escalate` (three `lockout_escalate` calls in order), `Reset` (one `DELETE FROM auth_lockouts`). Backed by `LockoutStore` (`pgxLockoutStore`). Steps 4 + recordOutcome escalate/reset.
  - **`SprayDetector`** (`spray.go`) — `Detect` → on hit: `LockIP` → `Audit` → `Notify`, in that order; zero writes when not detected. Backed by `SprayStore` (`pgxSprayStore`, calls `detect_spray()`). Step 5.
  - **`RateLimiter`** (`ratelimit.go`) — `Allow` upserts `rate_limit_counters` keyed `auth:PROTOCOL:IP`; `allowed = count <= RateLimitPerMin`. Backed by `RateLimitStore` (`pgxRateLimitStore`). Step 8.
  - The three `*Store` interfaces + pgx impls + `lockoutKeys()` helper live in `shared/threat/store.go`. Invariants pinned by `lockout_test.go`/`spray_test.go`/`ratelimit_test.go` (fakes); composition pinned by `interceptor_test.go`'s `TestIntercept_LockoutPath_*` (nil-pool + injected fakes; the step-2 IP-rules `ti.pool != nil` guard is a prod no-op enabling DB-free pipeline tests).
- **Fast path**: skip the whole pipeline (no DB) ONLY when every control is off — all six detection/rate toggles (threat_feed, geo_block, spray, captcha, tarpit, **rate_limit**) disabled AND no `policyEngine` (conditional access). Each must be represented: omitting one (rate_limit was missing) lets toggling on just that control silently bypass it (fail-open). `shared/threat/interceptor.go`
- **3 s DB query timeout**: wraps all interceptor DB calls to prevent login hangs. `shared/threat/interceptor.go`
- **HTTP middleware mode**: `Middleware(next)` — extracts meta from request body (login email or refresh token email), buffers body for handler re-injection, records post-auth outcome from HTTP status code. `shared/threat/interceptor.go`
- **`WithVerifiedNoOutcome`/postAuth semantic classification (wave-7)**: `postAuth` classifies by HTTP status (200/204 = success, else failure) UNLESS the handler stamped `ctx = threat.WithVerifiedNoOutcome(ctx)` (via `*r = r.WithContext(...)`, the same mutate-in-place pattern as `WithUserID` — the Middleware closure reads `rr.Context()` after `next.ServeHTTP` returns) — that response is recorded as NEITHER success nor failure (no `auth_attempts`/`login_events` write, no lockout escalate/reset). Fixes the bug where a password-verified-but-incomplete response (authserver's MFA-enrollment-required/force-password-change 403s, MFA-challenge/CA-step-up 202s) was counted as a failed login, so a legitimate user working through MFA could trip CAPTCHA/lockout on repeated CORRECT passwords. ## Work Guidance

- **No business logic**: these packages are adapters, contracts, and algorithms only. Anything with SQL reducers or protocol parsing belongs in the owning service.
- **Golangci-lint clean** before commit. Lint rules: no dupl (≥60 tokens), typed constants for discriminators, no dead code.
- **Every public function** that accepts user-supplied data must treat it as untrusted — never pass raw values to SQL, never log passwords.
- **Crypto profile awareness**: all code that derives keys or hashes passwords must accept / respect `CryptoProfile`. Never hardcode `AES` or `bcrypt` when the profile may be SMx.
- **`ValidationError` codes** must be ALL_CAPS snake-case strings (e.g. `EMPTY_EMAIL`, `DOT_SEQUENCE`) — client apps switch on these.
- **Toggle defaults**: use the finite registry and the owning observe/enforce mode contract. Add/classify a constant before relying on a new key; do not infer a universal unknown-key default.
- **Envelope format is stable**: never change `EnvelopeMagic`, the header layout, or existing `AlgorithmTag` values — old blobs must stay decryptable forever.
