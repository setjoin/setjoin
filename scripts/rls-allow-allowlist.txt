# ──────────────────────────────────────────────────────────────────────────
# rls-allow-allowlist.txt — the human-maintained ALLOW-TEST classification
# read by scripts/check-rls-allow.sh.
#
# Every FORCE'd table that BOTH (a) a reducer writes and (b) carries at least
# one write-capable RLS policy must have exactly one entry here. The guard
# computes that required set itself (FORCE'd tables ∩ reducer writers ∩
# write-capable policy, all derived live from the schema/reducer source) — a
# table with no reducer writer, or with only a FOR SELECT policy (worker/
# BYPASSRLS-only writes — e.g. user_risk, session_activity), needs NO entry
# at all: it is auto-excluded every run, nothing to hand-maintain.
#
# This file only says, per REQUIRED table, whether a genuine as-setjoin_app
# ALLOW-flow proof exists yet, and if so, where.
#
# An "allow-flow proof" is NOT "the policy exists" or "a foreign tenant is
# denied" (that's check-rls-denial.sh's job) — it is a pgTAP case that runs
# as a non-owner role (SET LOCAL ROLE setjoin_app — the test connection
# `mail` is a SUPERUSER + table owner and bypasses RLS even under FORCE, so
# the role switch is load-bearing) and asserts the table's own LEGITIMATE
# writer (its owning reducer, called with the correct
# app.current_user_id / app.current_mailbox_id GUC) actually SUCCEEDS —
# not merely that it doesn't throw, but that the written row is readable
# back under the same GUC.
#
# FORMAT (TAB-separated, 5 fields) — identical shape to
# scripts/rls-denial-allowlist.txt:
#   <table>\t<STATUS>\t<file>\t<substring>\t<reason>
#   · <table>     — exact table name.
#   · <STATUS>    — COVERED | PENDING.
#   · <file>      — for COVERED: the basename of the mailserver/sql/tests/*.pg
#                   file carrying the proof. For PENDING: "-".
#   · <substring> — for COVERED: a unique, stable substring of the file's own
#                   success assertion (the pgTAP description is a good pick —
#                   it changes if the test is weakened/renamed/deleted,
#                   re-tripping the guard). For PENDING: "-".
#   · <reason>    — one line. For PENDING, name the gap (or, where building
#                   the proof surfaced a REAL bug rather than a missing test,
#                   name the bug and point at the owning file/reducer).
#
# The guard verifies, for every COVERED row: <file> exists under
# mailserver/sql/tests/, contains <substring>, AND contains a SET [LOCAL]
# ROLE line — a deleted/gutted/renamed test re-fails the guard.
#
# PENDING rows do NOT fail the guard (that is how a fresh gap is seeded
# green — same convention as rls-denial-allowlist.txt); they DO show up in
# the guard's summary count so the gap stays visible on every run.
#
# Lines beginning with `#` (and blank lines) are ignored.
# ──────────────────────────────────────────────────────────────────────────
