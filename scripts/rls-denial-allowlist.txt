# ──────────────────────────────────────────────────────────────────────────
# rls-denial-allowlist.txt — the human-maintained DENIAL-TEST classification
# read by scripts/check-rls-denial.sh.
#
# Every table with `... FORCE ROW LEVEL SECURITY` in mailserver/sql/dbschema
# (baseline + migrations) must have exactly one entry here. The guard computes
# the FORCE'd-table set itself (it does not trust this file for that part) —
# this file only says, PER FORCE'd TABLE, whether a genuine cross-tenant
# DENIAL test exists yet, and if so, where.
#
# A "denial test" is NOT "RLS is enabled" or "the owning role can read its own
# row" — it is a pgTAP case that runs as a non-owner role (SET LOCAL ROLE
# setjoin_app / setjoin_worker — the test connection `mail` is a SUPERUSER +
# table owner and bypasses RLS even under FORCE, so the role switch is
# load-bearing) with TWO tenants' rows present, and asserts the OTHER tenant's
# row is inaccessible (a 0-count SELECT, a no-op UPDATE/DELETE, or a 42501).
#
# FORMAT (TAB-separated, 5 fields):
#   <table>\t<STATUS>\t<file>\t<substring>\t<reason>
#   · <table>     — exact table name (matches the ALTER TABLE ... FORCE target).
#   · <STATUS>    — COVERED | PENDING.
#   · <file>      — for COVERED: the basename of the mailserver/sql/tests/*.pg
#                   file carrying the proof. For PENDING: "-".
#   · <substring> — for COVERED: a unique, stable substring of the file's own
#                   denial assertion (pgTAP description string is a good pick —
#                   it changes if the test is weakened/renamed, re-tripping the
#                   guard). For PENDING: "-".
#   · <reason>    — one line. For PENDING, name the gap so it's gently visible
#                   (not a silent debt): a follow-up test to write.
#
# The guard verifies, for every COVERED row: <file> exists under
# mailserver/sql/tests/, contains <substring>, AND contains a SET LOCAL ROLE /
# SET ROLE line — so a deleted/gutted test re-fails the guard instead of the
# classification silently going stale.
#
# PENDING rows do NOT fail the guard (that's how a fresh gap is seeded green —
# see the production-hardening / native-RLS backstop programs); they DO show
# up in the guard's summary count so the gap stays visible on every run. A
# brand-new FORCE'd table with NO entry at all (neither COVERED nor PENDING)
# FAILS — that's the regression backstop: a migration can't silently add
# FORCE without a human decision recorded here.
#
# Lines beginning with `#` (and blank lines) are ignored.
# ──────────────────────────────────────────────────────────────────────────
